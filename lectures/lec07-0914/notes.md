## 1. 热身：不可区分实验（完美版）

> 出处：K&L §2.1 末尾（书页 30–31）

### 严格说法

实验 $\mathsf{PrivK}^{\mathsf{eav}}_{A,\Pi}$（eav = eavesdropping，窃听）：

> 1. 攻击者 $A$ 输出一对消息 $m_0, m_1 \in \mathcal{M}$。
> 2. 用 $\mathrm{Gen}$ 生成密钥 $k$，并均匀抽取一个比特 $b \in \{0,1\}$；计算 $c \leftarrow \mathrm{Enc}_k(m_b)$ 交给 $A$。这个 $c$ 叫 **challenge ciphertext**。
> 3. $A$ 输出一个比特 $b'$。
> 4. 若 $b' = b$，实验输出 1，称 $A$ **成功**；否则输出 0。

> **DEFINITION 2.5** 加密方案 $\Pi$ 是 **perfectly indistinguishable** 的，若对**每一个**攻击者 $A$ 都有
>
> $\Pr[\mathsf{PrivK}^{\mathsf{eav}}_{A,\Pi} = 1] = \tfrac{1}{2}$

> **LEMMA 2.6** $\Pi$ 完美保密 $\iff$ $\Pi$ 完美不可区分。

### 大白话

这是一个**猜谜游戏**：

```
① 攻击者自己挑两条消息 m₀、m₁，交给系统
② 系统私下抛硬币得到 b，加密 m_b，把密文 c 交给攻击者
③ 攻击者猜：你加密的是第 0 条还是第 1 条？
④ 猜对就算赢
```

瞎猜就能赢一半，所以 $\frac12$ 是底线。==完美不可区分 = 任何攻击者都不能比瞎猜更好==，哪怕他算力无限（书上原话："no limitations are placed on the computational power of $A$"）。

Lemma 2.6 说的是：这和 Lec 4 的完美保密（后验 = 先验）是**同一件事的两种说法**，一个从"猜原文"的角度讲，一个从"玩游戏"的角度讲。

### 老师板书的写法

```
攻击者 A ──── {m₀, m₁} ────▶ ┌ Verifier ─────────┐
                             │ k ~ GEN            │
                             │ b ~ {0,1}          │
攻击者 A ◀──── c ─────────── │ c ← Enc(k, m_b)    │
                             └────────────────────┘
攻击者 A ──── b' ───────────▶  test  b ≟ b'

Perfect Secure:  Pr[b = b'] = 1/2
```

和书上一模一样，只是老师把出题的一方叫 **Verifier**。

### 例子：你已经做过了

HW1 Q7 的原型就是书上 **Example 2.7**（Vigenère 密码不是完美不可区分的）。Q7 里那个用 $\Delta$ 函数的攻击者赢的概率是 $\frac23 > \frac12$，所以随机周期 Vigenère ==不是==完美不可区分的。

### 为什么这节课要先复习它

书上原话：这个实验 "will serve as our **starting point** for defining computational security in the next chapter"。

第 3 步要做的，就是在这个游戏上放宽**两处**：

| | 完美版（Ch 2） | 计算版（Ch 3） |
| :--- | :--- | :--- |
| 管哪些攻击者 | 所有攻击者，算力无限 | 只管**多项式时间**的攻击者 |
| 胜率要求 | **恰好** $\frac12$ | $\le \frac12 + $ **可忽略**的一点点 |

"可忽略"到底是多小，就是第 2 步要讲的 negligible 函数。

## 2. Negligible 函数

> 出处：K&L §3.1.2 Definition 3.4、Proposition 3.6（书页 48–49）；板书 ⑦

### 严格说法

> **DEFINITION 3.4** 函数 $f: \mathbb{N} \to \mathbb{R}_{\ge 0}$ 是 **negligible**（可忽略）的，若对**每一个**正多项式 $p$，都存在 $N$，使得对所有 $n > N$：
>
> $f(n) < \frac{1}{p(n)}$

等价写法：对每个常数 $c$，$n$ 足够大时 $f(n) < n^{-c}$。任意一个可忽略函数通常记作 $\mathsf{negl}(n)$。

### 大白话

> ==只要 $n$ 够大，它就比「1 / 任何多项式」都小。==

| 函数 | 可忽略吗 | 原因 |
| :--- | :-: | :--- |
| $2^{-n}$ | ✓ | 指数衰减，最终比任何 $1/n^c$ 都小 |
| $2^{-\sqrt n}$、$n^{-\log n}$ | ✓ | 衰减慢一些，但仍比任何多项式倒数小 |
| $1/n^{10}$ | ✗ | 它本身就是「1/多项式」：取 $p(n) = n^{11}$，永远有 $1/n^{10} > 1/n^{11}$ |

### 例子：为什么 $1/n^{10}$ 不算可忽略

设 $n = 128$，攻击者把攻击重复 $n^{11} = 2^{77}$ 次（重复次数是多项式，合法）：

```
单次成功率 1/n¹⁰：   2⁷⁷ × 1/128¹⁰ = 2⁷⁷ × 2⁻⁷⁰ = 2⁷ = 128   → 远超 1，几乎必成功  ✗
单次成功率 2⁻ⁿ：     2⁷⁷ × 2⁻¹²⁸  = 2⁻⁵¹ ≈ 4×10⁻¹⁶         → 依然极小           ✓
```

==「1/多项式」的成功率，重复多项式次就能放大到必成功；可忽略的成功率，重复多项式次也放大不起来。==

这就是定义里要打败「**每一个**」多项式的原因：攻击者可以跑任意多项式时间，所以成功率必须比所有 $1/p(n)$ 都小。

### 封闭性：PROPOSITION 3.6

> 1. $\mathsf{negl}_1(n) + \mathsf{negl}_2(n)$ 仍可忽略
> 2. 对任意正多项式 $p$，$p(n) \cdot \mathsf{negl}(n)$ 仍可忽略

**大白话：** 第 2 条就是上面那个例子 —— ==可忽略概率的事件，重复多项式次，仍然可忽略==。

所以「多项式时间攻击者」和「可忽略成功率」是**天生一对**：攻击者怎么在多项式范围内重复，都放大不了可忽略的概率。

### 老师板书的写法

```
ε to be negligible:    ε(n) < 1/p(n)    ∀ polynomial p
```

和 Def 3.4 一致，只是省略了「$n$ 足够大时」。这个条件不能真省：$2^{-n}$ 在 $n = 1$ 时等于 $\frac12$，一点也不小；可忽略说的是 $n$ 变大以后的趋势。

## 3. 计算安全的定义

> 出处：K&L §3.2 Definition 3.7–3.9（书页 52–56）；板书 ⑥⑦

### 先拆记号：$\mathsf{PrivK}^{\mathsf{eav}}_{A,\Pi}(n)$ 是什么

它就是**一个实验的名字加几个参数**，像函数调用一样读：

```
PrivK ^eav _A,Π (n)
  │      │    │ │   │
  │      │    │ │   └─ n    ：安全参数，大致就是钥匙长度（比如 128）
  │      │    │ └───── Π    ：被测试的加密方案，Π = (Gen, Enc, Dec)
  │      │    └─────── A    ：攻击者（Adversary）
  │      └──────────── eav  ：攻击类型 = eavesdropping，窃听
  └─────────────────── PrivK：Private-Key，私钥加密的安全实验
```

合起来读：「**私钥加密的窃听实验：让攻击者 $A$ 去攻击方案 $\Pi$，安全参数取 $n$**」。

| 记号 | 含义 | 补充 |
| :--- | :--- | :--- |
| PrivK | Private-Key，私钥加密 | 公钥加密会换成 PubK |
| eav | eavesdropping，窃听：攻击者只能偷看一个密文 | 就是 Lec 6 的 ciphertext-only attack。Lec 8 会出现 $\mathsf{PrivK}^{\mathsf{cpa}}$，右上角一换，攻击者能力就变强 |
| $A$ | Adversary，攻击者 | 试图猜出 $b$ 的那个算法 |
| $\Pi$ | 被测试的加密方案 | 只是个名字，就像用 $f$ 表示一个函数 |
| $n$ | 安全参数 | 直接当成**钥匙长度**。$n$ 越大越安全，攻击者的时间和胜率都按 $n$ 衡量 |
| $= 1$ | 实验结果为 1，即攻击者赢了 | $\Pr[\cdots = 1]$ 就是攻击者的胜率 |
| $1^n$ | $n$ 个 1 连在一起 | 就是"把 $n$ 告诉攻击者"，写成这样是技术细节，可忽略 |
| ppt | probabilistic polynomial-time | 多项式时间的（随机）算法 |
| $\mathsf{negl}(n)$ | 某个可忽略函数 | 第 2 步 |

**于是 Def 3.8 翻译过来就是：** 对每一个多项式时间的攻击者 $A$，$A$ 去玩「攻击方案 $\Pi$ 的窃听游戏（钥匙长度 $n$）」，==赢的概率最多比 $\frac12$ 多一个可忽略的量==。
### 严格说法

实验 $\mathsf{PrivK}^{\mathsf{eav}}_{A,\Pi}(n)$ —— 和第 1 步几乎一样，**加粗**的是新增的地方：

> 1. 攻击者 $A$ **收到安全参数 $1^n$**，输出一对消息 $m_0, m_1$，**要求 $|m_0| = |m_1|$**。
> 2. 运行 $\mathrm{Gen}(1^n)$ 生成密钥 $k$，均匀抽取 $b \in \{0,1\}$，把 $c \leftarrow \mathrm{Enc}_k(m_b)$ 交给 $A$。
> 3. $A$ 输出 $b'$。
> 4. 若 $b' = b$，实验输出 1（$A$ 成功）。

> **DEFINITION 3.8（EAV-secure）** $\Pi$ 在窃听者面前具有不可区分的加密（简称 **EAV-secure**），若对**每一个** ppt 攻击者 $A$，都存在可忽略函数 $\mathsf{negl}$，使得对所有 $n$：
>
> $\Pr[\mathsf{PrivK}^{\mathsf{eav}}_{A,\Pi}(n) = 1] \le \tfrac12 + \mathsf{negl}(n)$
>
> 概率取自 $A$ 的随机性，以及实验里的随机性（选密钥、选 $b$、$\mathrm{Enc}$ 的随机性）。

ppt = probabilistic polynomial-time，即多项式时间的随机算法。

> **DEFINITION 3.9（等价写法）** 把 $b$ 固定下来跑实验，记为 $\mathsf{PrivK}^{\mathsf{eav}}_{A,\Pi}(n, b)$。要求对每个 ppt 的 $A$：
>
> $\bigl|\Pr[A \text{ 在 } b{=}0 \text{ 时输出 } 1] - \Pr[A \text{ 在 } b{=}1 \text{ 时输出 } 1]\bigr| \le \mathsf{negl}(n)$

### 大白话

**游戏不变，只把规则放宽两处：**

| | 完美版（第 1 步） | 计算版（这一步） |
| :--- | :--- | :--- |
| 管哪些攻击者 | 所有攻击者，算力无限 | ==只管多项式时间的== |
| 胜率要求 | 恰好 $\frac12$ | ==$\le \frac12 +$ 可忽略== |
| 消息长度 | 不用管（OTP 的消息本来就定长） | ==$m_0, m_1$ 必须一样长== |

> **一句话：** 算力正常的攻击者，胜率只能比瞎猜多出一个可忽略的量。

**Def 3.9 换了个角度说同一件事：** 攻击者不管拿到的是 $m_0$ 还是 $m_1$ 的密文，=="反应"几乎一样==（输出 1 的概率只差一个可忽略的量）。反应一样，就说明他分不出来。

### 例子：一个不满足 EAV 安全的方案

设加密时第一位明文**原样保留**，其余位和钥匙异或：

```
攻击者挑：   m₀ = 0000…0       m₁ = 1000…0      （长度一样，合法）
收到密文 c：看 c 的第一位
             是 0 → 猜 b' = 0
             是 1 → 猜 b' = 1
```

每次必中，胜率 $= 1$，远大于 $\frac12 + \mathsf{negl}(n)$ ——==不是 EAV-secure==。哪怕只泄露一个比特，也会被这个游戏抓出来。

### 为什么要放宽：这一步的真正目的

Def 3.8 比完美版（Def 2.5）**弱**，所以：

```
完美版：钥匙必须 ≥ 消息长度（Lec 4 的 |K| ≥ |M|）
计算版：==不受这个限制==，有希望用短钥匙加密长消息
```

书上原话：我们的目标就是造出「**钥匙比消息短、却满足 Def 3.8**」的方案 —— 这在完美版下是不可能的。怎么造？要用第 4 步的 PRG，第 6 步证明它真的满足 Def 3.8。

### 一个细节：默认不隐藏消息长度

要求 $|m_0| = |m_1|$，等于承认==加密方案不负责隐藏明文长度==。否则攻击者挑一长一短，看密文长度就赢了。

长度泄露有时很要命，书上举的例子：

- 加密工资，密文长度暴露是五位数还是六位数
- 加密 "yes" / "no"，长度直接暴露答案
- 先压缩再加密，压缩后的长度泄露内容的冗余程度（真实的 CRIME 攻击就利用了这点）

需要隐藏长度时，要先把所有消息**填充到统一长度**再加密。

### 老师板书的写法

```
Limit the computational power of Adv:    A in P
Π is ε-secure (computationally) if  Pr[b = b'] ≤ 1/2 + ε   for any poly-time Adv
ε to be negligible
```

和 Def 3.8 一致：先限制攻击者算力，再要求胜率 $\le \frac12 + \varepsilon$，最后要求 $\varepsilon$ 可忽略。

## 4. PRNG 的定义

> 出处：K&L §3.3.1 Definition 3.14、Example 3.15（书页 60–64）；板书 ⑤

### 一句话

> ==把一小段真随机（种子，$n$ 位）拉长成一大段「看起来随机」的串（$L(n)$ 位，$L(n) > n$）。==

```
种子 s（n 位，真随机）  ──G──▶  G(s)（L(n) 位，伪随机）
```

$G$ 本身是**确定性**的：同一个种子永远输出同一个结果。随机性全部来自种子。

### 严格说法

> **DEFINITION 3.14** 设 $G$ 是多项式时间的确定性算法，对任意 $n$ 和输入 $s \in \{0,1\}^n$，输出 $G(s)$ 的长度为 $\ell(n)$。$G$ 称为 **pseudorandom generator**，若：
>
> 1. **（Expansion，拉长）** 对每个 $n$，$\ell(n) > n$。
> 2. **（Pseudorandomness，伪随机）** 对每个 ppt 算法 $D$，存在可忽略函数 $\mathsf{negl}$，使得
>
>    $\bigl|\Pr[D(G(s)) = 1] - \Pr[D(r) = 1]\bigr| \le \mathsf{negl}(n)$
>
>    其中 $s$ 是均匀随机的 $n$ 位种子，$r$ 是均匀随机的 $\ell(n)$ 位串。
>
> $\ell$ 叫 $G$ 的 **expansion factor**。

### 大白话

**区分器 $D$ = 一个测试**：吃进一个串，输出 1 或 0（"我觉得它是 $G$ 生成的" 或 "我觉得是真随机的"）。

第 2 条说：把 $G$ 的输出和真随机串分别拿给 $D$ 测，==$D$ 输出 1 的概率几乎一样==，也就是任何高效的测试都分不出两者。

这和第 3 步的 Def 3.9（攻击者在两个世界里"反应"几乎一样）是**同一个套路**。书上也这么说：伪随机之于真随机，就像 EAV 安全之于完美保密，都是"计算版的放宽"。

### 例子：一个不合格的 PRNG（Example 3.15）

$G(s)$ = 在 $s$ 后面补一位：$s$ 所有位的异或（奇偶校验位）。

```
n = 3，s = 101   →   1⊕0⊕1 = 0   →   G(s) = 1010
```

区分器 $D$：检查"最后一位是否等于前面所有位的异或"，是就输出 1。

```
喂 G 的输出：   永远满足        →  Pr = 1
喂真随机串：    最后一位随机    →  Pr = 1/2

差 = 1/2，不是可忽略  →  不是 PRNG
```

### 关键点：伪随机串其实一点也不均匀

```
n = 128，ℓ = 256：
  256 位的串一共 2²⁵⁶ 种
  G 最多只能输出 2¹²⁸ 种（种子只有这么多）
  → 绝大多数 256 位的串，G 根本输出不了
```

所以**算力无限**的话很容易分辨：把 $2^{128}$ 个种子全试一遍，看这个串在不在里面。但这要指数时间，不算"高效"，**不违反定义**。

> ==伪随机 = 只对多项式时间的观察者看起来随机。==

### 其他

- **种子就相当于钥匙**：必须均匀随机、保密、足够长（否则穷举种子就破了）。
- **PRNG 存在吗？** 没有被证明。但只要单向函数存在（比如大整数分解很难）就能造出来，Ch 7 讲。

### 老师板书的写法

| 老师 | 书上 |
| :--- | :--- |
| $\varphi$ | $G$ |
| $B$（Boolean function） | $D$（区分器） |
| $U^n$ | 均匀随机的 $n$ 位串 |
| ε-PRNG：$\bigl\lvert\Pr_{x \sim U^{L(n)}}[B(x)=1] - \Pr_{x \sim \varphi(U^n)}[B(x)=1]\bigr\rvert \le \varepsilon$ | Def 3.14：同样的差 $\le \mathsf{negl}(n)$ |

只是换了字母，意思一样。

## 5. 归约证明法

> 出处：K&L §3.3.2、Figure 3.1（书页 65–66）；板书 ④

### 为什么需要它

计算安全**没法无条件证明**——那需要先证明 $P \ne NP$ 之类的难题，没人做得到。

所以只能退一步，证一个**条件句**：

```
如果 X 很难（比如：没人能分辨 G 的输出和真随机）
那么 Π 就是安全的
```

### 核心逻辑：反过来证（逆否命题）

老师板书上框起来的那行：

$A \Rightarrow B \quad \text{等价于} \quad \neg B \Rightarrow \neg A$

日常例子：「下雨 ⇒ 地湿」等价于「地不湿 ⇒ 没下雨」。

套到密码学：

```
想证：   X 难  ⇒  Π 安全
改证：   Π 不安全  ⇒  X 不难
         即：如果有人能破 Π，那就能借他的手去解 X
```

**为什么改证更容易？** 因为「Π 安全」要对**所有**攻击者成立，没法一个个检查；而「有人能破 Π」给了你一个**具体的攻击者**当工具用。

### 做法：借刀

```
1. 假设存在一个高效攻击者 A，能以不可忽略的概率 ε(n) 攻破 Π

2. 造一个新算法 A'（这个 A' 就叫"归约"），把 A 当成子程序调用，用它去解 X：
   (a) A 感觉不到自己被利用：它看到的一切，和真的在攻击 Π 时一模一样
   (b) 只要 A 攻破了，A' 就能顺手把 X 解出来

3. 于是 A' 也能以不可忽略的概率解 X   →   和"X 难"矛盾

4. 所以这样的 A 根本不存在   →   Π 安全
```

==一个关键点：$A'$ 不知道 $A$ 内部是怎么工作的，只能把它当黑盒==：喂输入、拿输出。因为我们要对付的是**任意**攻击者，不能假设它用什么招数。

### 类比：锁的安全性

> 锁匠说：「我这把锁安全，因为它用的是银行金库那种公认撬不开的锁芯。」
>
> 怎么证明？「**如果你能撬开我这把锁，我就能拿你的方法去撬开金库锁芯。** 但大家公认金库锁芯撬不开，所以你也撬不开我的锁。」

```
金库锁芯撬不开   =  X 很难（假设）
我这把锁         =  Π
"拿你的方法"     =  把攻击者 A 当子程序用
```

### 这节课里具体是什么（第 6 步详细讲）

| 通用框架 | 这节课的具体化 |
| :--- | :--- |
| 难题 X | 分辨 $G$ 的输出和真随机串（因为 $G$ 是 PRG，所以难） |
| 方案 $\Pi$ | 用 $G$ 造出来的加密方案 |
| 攻击者 $A$ | 能以明显高于 $\frac12$ 的概率赢加密游戏的人 |
| 归约 $A'$ | 老师板书上的 **$B$**：把 $A$ 当子程序，用它来分辨 $G$ |

所以第 6 步要证的就是：==谁能破这个加密，谁就能分辨 $G$ 的输出==——而 $G$ 是 PRG，没人能分辨，所以没人能破这个加密。

### 为什么叫"归约"

把「破解 $\Pi$」这个问题**归结**（reduce）到「解 X」上：说明破解 $\Pi$ **至少和**解 X 一样难。

## 6. 主定理：PRNG ⟹ 安全加密 ⭐

> 出处：K&L §3.3.3 Construction 3.17、Theorem 3.18（书页 66–70）；板书 ⑧

### 先看方案本身（Construction 3.17）

**大白话：就是 OTP，只是钥匙换成「用 $G$ 拉长出来的」。**

> **CONSTRUCTION 3.17** 设 $G$ 是 expansion factor 为 $\ell$ 的 PRNG。对长度为 $\ell(n)$ 的消息定义：
>
> - $\mathrm{Gen}$：输入 $1^n$，均匀选取 $k \in \{0,1\}^n$ 作为钥匙
> - $\mathrm{Enc}$：输入 $k$ 和 $m \in \{0,1\}^{\ell(n)}$，输出 $c := G(k) \oplus m$
> - $\mathrm{Dec}$：输入 $k$ 和 $c$，输出 $m := G(k) \oplus c$

```
OTP：        钥匙本身就是 ℓ(n) 位真随机          → 双方要共享 ℓ(n) 位
这个方案：   钥匙只有 n 位，用时再拉长成 ℓ(n) 位  → 双方只共享 n 位
```

比如 $n = 128$、$\ell(n) = 256$：只共享 128 位，就能加密 256 位的消息。

### 定理

> **THEOREM 3.18** 若 $G$ 是 PRNG，则 Construction 3.17 是 EAV-secure 的（满足 Def 3.8）。

老师板书：「有 ε-PRNG（$n \to L(n)$）⟹ 能用 $n$ 位钥匙加密 $L(n)$ 位消息」。

### 证明思路：用第 5 步的逆否命题

```
要证：   G 是 PRNG  ⟹  方案安全
改证：   方案不安全  ⟹  G 不是 PRNG
即：     如果有攻击者 A 能破这个方案，就造一个区分器 B，用 A 来分辨 G 的输出
```

### 区分器 $B$ 怎么造（老师板书那 7 步）

$B$ 拿到一个 $\ell(n)$ 位的串 $s$，**不知道它是真随机的，还是 $G$ 拉长出来的**。$B$ 这样做：

```
1. 让攻击者 A 挑两条消息 m₀、m₁
2. （被老师划掉了，见下面）
3. 把拿到的串 s 直接当钥匙：  K = s
4. 抛硬币得 b
5. 加密：  c = K ⊕ m_b
6. 把 c 给 A，A 猜 b'
7. A 猜对了 → B 输出 1（"我觉得 s 是 G 生成的"）
   A 猜错了 → B 输出 0（"我觉得 s 是真随机的"）
```

==大白话：把要鉴定的串塞进加密里当钥匙用，看攻击者表现如何。==

（书上的区分器叫 $D$，把这 7 步合并成 3 步，内容一样。）

### ⭐ 为什么第 2 步被划掉

原来的第 2 步是「自己随机选种子 $k$，算 $K = G(k)$」。**这样做是错的**：

```
如果 B 自己生成钥匙 → 不管输入 s 是什么，B 都在模拟真实方案
                  → B 的输出跟 s 毫无关系
                  → 根本没在鉴定 s
```

**$B$ 的任务是鉴定输入的 $s$**，所以必须把 $s$ 本身当钥匙用。老师划掉第 2 步、改成 $K = s$，就是这个意思。==这是整个证明的关键。==

### 分析：两种情况下 $B$ 输出 1 的概率

```
情况一：s 是真随机的
   → 钥匙是真随机的 ℓ(n) 位 → 这就是 OTP
   → OTP 完美保密，A 只能瞎猜
   → A 猜对的概率 = 1/2
   → Pr[B 输出 1] = 1/2

情况二：s 是 G(k) 生成的
   → 这就是真实方案
   → 假设 A 能破它，猜对的概率 > 1/2 + ε
   → Pr[B 输出 1] > 1/2 + ε
```

两者相减：

$\bigl|\Pr[B \text{ 输出 } 1 \mid \text{伪随机}] - \Pr[B \text{ 输出 } 1 \mid \text{真随机}]\bigr| > \left(\tfrac12 + \varepsilon\right) - \tfrac12 = \varepsilon$

$\varepsilon$ 不可忽略 → **$B$ 能分辨 $G$ 的输出** → 和"$G$ 是 PRNG"矛盾 → 这样的 $A$ 不存在 → **方案安全**。$\blacksquare$

老师板书右边写的就是这两行：

```
Pr[B(s) = 1]，s 真随机        =  1/2
Pr[B(s) = 1]，s 由 φ 生成     >  1/2 + ε
```

这也正好满足第 5 步归约的两个要求：(a) 两种情况下 $A$ 看到的都和真实实验一模一样，它察觉不到被利用；(b) $A$ 占到的便宜，直接变成了 $B$ 的分辨能力。

### 一句话总结证明

> ==钥匙是真随机时，谁都占不了便宜（OTP）；只有钥匙是伪随机时，攻击者才可能占便宜。==所以"攻击者有没有占到便宜"，就暴露了"钥匙是不是伪随机的"——而 $G$ 是 PRNG，没人能看出来，所以攻击者也占不到便宜。

### 这个定理的意义

```
Lec 4 的 Theorem 2.10：完美保密 ⟹ 钥匙 ≥ 消息长度
这个定理：            计算安全下，128 位钥匙就能加密很长的消息
```

**我们绕开了 $|\mathcal{K}| \ge |\mathcal{M}|$ 的限制**，代价是：只对多项式时间的攻击者安全。这就是从 Lec 4 到这节课一路铺垫的目的。

## 7. 老师加的：复杂性背景（P、NP、RP）

> 出处：板书 ①（左上角一小块）；教材 §3.1–3.3 不讲。P、NP 见 [Lec 1 笔记](../lec01-0824/notes.md)。

### 板上写的

```
RP
P  vs  NP

Algorithm ─┬─ deterministic
           └─ randomized
```

P 和 NP 是 Lec 1 学过的，真正新的只有 **RP** 和「确定性 / 随机化」这组对比。

### 四个概念，各一句话

| 概念 | 一句话 |
| :--- | :--- |
| **P** | 确定性算法，多项式时间能解出来（Lec 1） |
| **NP** | 答案给你的话，多项式时间能验证（Lec 1，比如数独） |
| **deterministic** | 算法每一步都是定死的，同样输入永远同样输出 |
| **randomized** | 算法运行时可以自己抛硬币 |
| **RP** | 随机化算法，多项式时间，「只会错一边」 |

**RP 的"只会错一边"：**

```
答案是 NO   →  算法一定说 NO（绝不误报）
答案是 YES  →  算法至少一半概率说 YES（可能漏报）
```

漏报不要紧：重复跑 100 次，只要有一次说 YES 就是 YES，漏报概率降到 $2^{-100}$。

**例子：判断一个数是不是合数**（后面 RSA 生成大素数要用）。随机抽一个数去测试，如果测出"合数的证据"，那就一定是合数；如果是素数，永远测不出证据。这正好是 RP 的样子。

关系：$P \subseteq RP \subseteq NP$

### 老师为什么在这节课提这些

**1. 攻击者的定义里有随机性**

这节课的攻击者是 **ppt**（probabilistic polynomial-time），第一个 p 就是 probabilistic，允许抛硬币。老师提 randomized 和 RP，是在说明==随机化算法是正当的计算模型，攻击者可以用==。随机性有时真能帮大忙（比如上面判断合数，随机方法又快又简单）。

**2. 解释了第 4 步"PRNG 存在证明不出来"**

```
如果 P = NP：
  "给一个串 w，有没有种子 s 使 G(s) = w？"   ← 这是个 NP 问题（有 s 就能快速验证）
  → 它在 P 里 → 能快速判断
  → 能分辨 G 的输出和真随机串（真随机串几乎都不在 G 的输出范围里）
  → 不存在 PRNG
```

> ==反过来：PRNG 存在 ⟹ $P \ne NP$==

所以证明 PRNG 存在，至少和证明 $P \ne NP$ 一样难——这就是为什么只能**假设**它存在。

## 8. 老师加的：worst-case vs average-case hardness

> 出处：板书 ②（average-case 被框起来、下面画了线）；教材全书没有 "average-case" 这个词。

### 板上写的

```
worst-case  ─┐
average-case ┘→ hardness
```

### 两个概念

| 概念 | 意思 |
| :--- | :--- |
| **worst-case hard**（最坏情况难） | 没有高效算法能解决「所有」输入 → 只要存在「某些」难的输入就算，哪怕绝大多数输入都很简单 |
| **average-case hard**（平均情况难） | 「随机抽」一个输入，高效算法解出来的概率可忽略 → ==「绝大多数」输入都难== |

**类比：锁匠说"我的锁很难开"**

```
worst-case 的意思：   我造的锁里，至少有一把你打不开（其余可能一捅就开）
average-case 的意思： 我随便拿一把给你，你几乎肯定打不开
```

你买锁的时候，拿到的就是"随便一把"——**你要的是 average-case**。

### 为什么密码学必须要 average-case

因为==钥匙是随机生成的==，攻击者面对的是一个随机实例，不是最难的那个。

```
假设某个问题：一百万个实例里只有 1 个难，其余都很简单
  → 它算"最坏情况难"
  → 但你随机生成的钥匙，几乎一定落在简单的那 999,999 个里
  → 拿它做加密，完全没用
```

### 这节课学的定义，本身就是 average-case 的

回头看第 4 步 PRNG 的定义：

$\bigl|\Pr[D(G(s)) = 1] - \Pr[D(r) = 1]\bigr| \le \mathsf{negl}(n)$，其中 $s$ 是**均匀随机**的种子

说的是**随机抽一个种子**，$D$ 分辨不出来——而不是"存在某个种子 $D$ 分辨不出来"。第 3 步 EAV 安全的定义也一样，概率取自随机钥匙。

> ==「成功概率可忽略」这个写法，本身就是在要求 average-case 难。==

### 缺口：$P \ne NP$ 不够用

接上第 7 步：

```
第 7 步：   PRNG 存在  ⟹  P ≠ NP         （P ≠ NP 是必要条件）

但：        P ≠ NP 只说「NP 问题里存在难的实例」 ← worst-case
            密码学要「随机实例几乎都难」         ← average-case
            → 就算有人证明了 P ≠ NP，也还推不出 PRNG 存在
```

这正是 Lec 6 准备的问题 3：*"$P \neq NP$ is worst-case hardness, but cryptography needs average-case hardness. If $P \neq NP$ were proved tomorrow, would that be enough?"* ——老师这节课直接写到板上了。答案是：**不够**，中间还有这道缺口，目前没人能填上。

### 一个例外：格密码

格（lattice）问题是少数**已经证明了"最坏情况难 ⟹ 平均情况难"**的问题（Ajtai 1996）：只要格问题的最难实例是难的，随机实例也就是难的。这是格密码被看好的原因之一。

## 9. 老师加的：Shannon's Theorem

> 出处：板书 ③；K&L §2.4 Theorem 2.11（书页 36–37，标 `*` 选读，Lec 4 没讲）

板上那句话：

> **"One time pad is essentially the only scheme for perfect communication."**
> ——OTP 基本上是唯一的完美保密方案。

这句话的严格版本就是 **Shannon 定理**。

### 严格说法

> **THEOREM 2.11（Shannon's theorem）** 设加密方案满足 $|\mathcal{M}| = |\mathcal{K}| = |\mathcal{C}|$。该方案完美保密，**当且仅当**：
>
> 1. 每把钥匙 $k \in \mathcal{K}$ 被 $\mathrm{Gen}$ 选中的概率相同，都是 $1/|\mathcal{K}|$；
> 2. 对每个 $m \in \mathcal{M}$ 和每个 $c \in \mathcal{C}$，**恰好存在一把**钥匙 $k$ 使 $\mathrm{Enc}_k(m) = c$。

### 大白话

> ==在"钥匙刚好够用"的情况下，完美保密只有一种长法：钥匙均匀选，而且任意一对明文和密文之间，恰好有一把钥匙连着。==

这正是 OTP 的结构，所以说"OTP 基本上是唯一的"——不是说只能用异或，而是**任何这种方案，骨子里都长得和 OTP 一样**。

为什么要求三者一样大？Lec 4 学过 $|\mathcal{K}| \ge |\mathcal{M}|$（完美保密要求），而正确解密要求 $|\mathcal{C}| \ge |\mathcal{M}|$。三者一样大是最省的情况。

### 例子 1：P5(b)，$\mathbb{Z}_3$ 上的 OTP

$\mathrm{Enc}_k(m) = m + k \bmod 3$，列出全部加密结果：

```
         m=0   m=1   m=2
  k=0     0     1     2
  k=1     1     2     0
  k=2     2     0     1
```

```
条件 1：钥匙均匀，各 1/3                                         ✓
条件 2：随便挑一对，比如 m=1、c=0，只有 k=2 能做到（1+2=3≡0）      ✓
        表里每一列 0、1、2 各出现一次，所以每对都恰好一把
```

**两条都满足 → 完美保密。** 不用算任何概率。

### 例子 2：P5(c)，钥匙有偏

同一个方案，但 $\Pr[K=0] = \frac12$，$\Pr[K=1] = \Pr[K=2] = \frac14$：

```
条件 1：钥匙不均匀   ✗   →   不是完美保密
```

P5(c) 里算了一大串 Bayes，得出后验 $\frac12 \ne$ 先验 $\frac13$。用 Shannon 定理，==看一眼条件 1 就知道结论==。

### 证明思路（各一句）

```
⇐  两条都满足：Pr[密文=c | 明文=m] = 那唯一一把钥匙的概率 = 1/|K|，跟 m 无关
               → 和 OTP 的证明一模一样，Bayes 上下约掉

⇒  完美保密：每条明文都必须能变成 c（否则攻击者能排除它，和 |K| ≥ |M| 的论证一样）
             空间一样大 → 每对恰好一把钥匙
             钥匙概率不相等 → 不同明文变成 c 的概率就不同 → 泄露信息
```

### 有什么用

**判断一个方案是不是完美保密，不用算概率，只要检查两个条件。** 条件 1 看一眼 $\mathrm{Gen}$，条件 2 列个表就行。

**注意：只在 $|\mathcal{M}| = |\mathcal{K}| = |\mathcal{C}|$ 时能用。** 三个空间大小不同时，这个定理不适用。
