这节课开始，主要是以下这些变化。

```
之前（私钥 / 对称）：   一把钥匙 k
                       Enc_k(m) → c        加密用 k
                       Dec_k(c) → m        解密也用 k
                       k 必须双方都有，还得保密

现在（公钥 / 非对称）： 一对钥匙 (pk, sk)
                       Enc(pk, m) → c      加密用公钥
                       Dec(sk, c) → m      解密用私钥
                       pk 公开给所有人，sk 只有接收方有
```

补两点：

1. **两把钥匙不是各自随便选的**，是 Gen 一次**成对**生成的，数学上配套。用 pk 加密的东西，只有配套的 sk 能解开。

2. **攻击者也知道 pk**，因为它是公开的。这是和之前最大的不同，第 3 步 CPA 就从这里来：攻击者手里有 pk，想加密什么就能自己加密什么。


## 1. 为什么需要公钥：钥匙分发问题

出处：K&L §10.1、§10.4（书页 359–360、370–374）；板书 ①

**问题：钥匙最开始怎么共享？**

Lec 4–7 的私钥加密都假设**双方已经有同一把钥匙**。但这把钥匙不能直接在网上发，会被窃听。

三个麻烦（§10.1）：

```
① 分发：    只能见面交接，或派信使送（Lec 4 的"红色电话"就是这么干的）
② 管理：    N 个人两两通信，每人要存 N−1 把
            N = 1000 时，全公司一共 499,500 把
③ 开放系统：网购时和从没见过的商家通信，根本没机会事先交换钥匙
```

①② 在封闭组织里还能勉强解决（设一个大家都信任的密钥分发中心，§10.2）；③ 私钥加密完全解决不了。

> [!tip]
> 这些都是很好理解的

**解决：公钥加密（Diffie & Hellman，1976）**

每人生成一对钥匙：公钥 $pk$ 公开、用来加密；私钥 $sk$ 保密、用来解密。

知道公钥也解不开，所以公钥可以大方地挂在网上。

**私钥 vs 公钥：一把钥匙变成两把**

```
之前（私钥 / 对称）：   一把钥匙 k
                       Enc_k(m) → c        加密用 k
                       Dec_k(c) → m        解密也用 k
                       k 必须双方都有，还得保密

现在（公钥 / 非对称）： 一对钥匙 (pk, sk)
                       Enc(pk, m) → c      加密用公钥
                       Dec(sk, c) → m      解密用私钥
                       pk 公开给所有人，sk 只有接收方有
```

补两点：

1. **两把钥匙不是各自随便选的**，是 $\mathrm{Gen}$ 一次**成对**生成的，数学上配套。用 $pk$ 加密的东西，只有配套的 $sk$ 能解开。
2. 攻击者也知道 $pk$，因为它是公开的。这是和之前最大的不同，第 3 步 CPA 就从这里来：攻击者手里有 $pk$，想加密什么就能自己加密什么。

> [!tip]
> 这一节还是很简单的，很容易理解。 \
> 这也是为什么，为啥我们要讲cpa，因为大家都有公钥

## 2. 公钥加密的语法和正确性

出处：K&L §11.1、§11.2（书页 375–379）；板书 ①

### 严格定义

**DEFINITION 11.1** 公钥加密方案是三个 ppt 算法 $(\mathrm{Gen}, \mathrm{Enc}, \mathrm{Dec})$：

1. $\mathrm{Gen}(1^n)$ 输出一对钥匙 $(pk, sk)$，分别叫**公钥**和**私钥**。
2. $\mathrm{Enc}$ 输入公钥 $pk$ 和消息 $m$，输出密文，记作 $c \leftarrow \mathrm{Enc}_{pk}(m)$。（$\mathrm{Enc}$ 要做到有意义的安全，必须是随机的。）
3. $\mathrm{Dec}$ 是**确定性**的，输入私钥 $sk$ 和密文 $c$，输出消息 $m$ 或失败符号 $\bot$，记作 $m := \mathrm{Dec}_{sk}(c)$。

**正确性：** 除了可忽略的概率外，对 $\mathrm{Gen}(1^n)$ 输出的 $(pk, sk)$ 和任意合法消息 $m$，都有 $\mathrm{Dec}_{sk}(\mathrm{Enc}_{pk}(m)) = m$。


### 对比

|              | 纯私钥版（对称版）       | 公私钥版 （非对称版）|
| :----------- | :--------- | :---------------------------------- |
| Gen 输出     | 一把 $k$   | **一对** $(pk, sk)$                 |
| 加密、解密用 | 同一把 $k$ | 加密用 $pk$，解密用 $sk$            |
| Enc 随机吗   | 可以随机   | **‼️必须随机**（第 3 步讲为什么） |
| 正确性       | 100% 成立  | 允许**可忽略概率**出错              |

**为什么允许出错？** 造钥匙时要随机找大素数，用的是 Lec 7 讲的那种随机测试，有极小概率把合数误当成素数，钥匙就坏了。概率可忽略，所以允许。


### 一个小 RSA 的例子

**它在干嘛（一句话）**

```
加密：把消息 m 算 3 次方，再除以 33 取余数
解密：把密文 c 算 7 次方，再除以 33 取余数
```

公开的是 **33 和 3**，保密的是 **7**。

**加密 m = 4**

```
4³ = 4 × 4 × 4 = 64
64 ÷ 33 = 1 余 31
→ 密文 c = 31
```

**解密 c = 31：算 31⁷ 除以 33 的余数**

直接算 31⁷ 太大，**边乘边取余数**（就像 HW1 里做的模约简）：

```
31²  = 961          961 = 33 × 29 + 4     →  余 4
31⁴  = (31²)²  →    4 × 4 = 16                →  余 16
31⁶  = 31⁴ × 31²  → 16 × 4 = 64 = 33 + 31      →  余 31
31⁷  = 31⁶ × 31   → 31 × 31 = 961             →  余 4
```

**拿回 m = 4** ✓

**再验几个**

```
m = 2    加密 2³ = 8          解密 8⁷ mod 33 = 2    ✓
m = 5    加密 5³ mod 33 = 26   解密 26⁷ mod 33 = 5   ✓
m = 7    加密 7³ mod 33 = 13   解密 13⁷ mod 33 = 7   ✓
```

每次都能拿回原来的数。

**为什么解得回来（简版，Lec 9 细讲）**

先 3 次方、再 7 次方，等于一共算了 **21 次方**。关键是这三个数是这样选的：

```
33 = 3 × 11
20 = (3 − 1) × (11 − 1)
3 × 7 = 21 = 20 + 1
```

数论里有个定理：在 mod 33 下，任何（和 33 互素的）数的 **20 次方都等于 1**。所以 21 次方 = 20 次方 × 1 次方 = 1 × m = **m**，转了一圈回到原点。

**为什么别人解不开**

```
想解密  →  需要 7
想算 7  →  需要 20（得先知道 20，才能找到满足 3 × 7 = 20 + 1 的 7）
想算 20 →  需要知道 33 = 3 × 11，也就是把 33 分解开
```

33 太小，一眼就能分解。真实的 RSA 用的是**几百位的数**，分解它现在做不到——这就是 RSA 的安全性所在。

这个例子现在只是个预告，Lec 9 会把「为什么 20 次方等于 1」讲清楚。能看懂加密、解密这两步怎么算就够了。

## 3. CPA：选择明文攻击

> **一句话：攻击者不只能偷看密文，还能自己挑明文，让系统替他加密。**

Lec 6 的四种攻击模型里，这是第 ③ 种。

### 真实例子：中途岛战役（1942）

```
美军截获日军密电，破译出一部分：日军要进攻 "AF"，但不知道 AF 是哪
美军怀疑是中途岛，于是故意让中途岛发一条假消息："我们缺淡水了"
日军截获后，加密上报："AF 缺淡水"
美军再截获这条密电 → 确认 AF = 中途岛
```
美军控制了日军要加密的内容，这就是选择明文攻击。

### 严格说法：CPA 实验（私钥版，K&L Def 3.22）

和第 3 节（Lec 7）的猜谜游戏一样，只多了一样东西：攻击者全程可以用一台"加密机"：

```
1. 生成钥匙 k
2. 攻击者随便用加密机：想加密什么就塞进去，拿回密文
   然后挑两条消息 m₀、m₁
3. 系统抛硬币得 b，把 m_b 的密文 c 给攻击者
4. 攻击者还可以继续用加密机，最后猜 b'
5. 猜对算赢
```

**CPA 安全 = 多项式时间的攻击者，胜率 ≤ 1/2 + 可忽略。**

加密机里装着钥匙 k，攻击者看不到 k，只能喂明文、拿密文。书上叫它 encryption oracle。

### ⭐ 反直觉的结论：确定性加密一定不 CPA 安全

确定性 = 同一条消息，每次加密结果都一样。攻击者这样打：

```
1. 先用加密机加密 m₀，记下结果 c₀
2. 拿到挑战密文 c 后，比一下：
   c = c₀  →  猜 b' = 0
   c ≠ c₀  →  猜 b' = 1
```

百分之百赢。

拿迷你 RSA 看： 它是确定性的，4 永远加密成 31。攻击者拿公钥自己加密一下 4，得到 31，再和截获的密文一比，就知道是不是 4。

所以 CPA 安全的加密必须是随机的：同一条消息每次加密出不同的密文，但都能正确解密回来。怎么做到，后面会学。

这不是定义太苛刻。书上的例子：学生加密一串"对/错"答案，如果是确定性的，看密文就知道哪些题答案相同。

### 公钥版：窃听安全自动就是 CPA 安全

公钥版的窃听游戏（PubK^eav，K&L Def 11.2）只改了一处：攻击者一开始就拿到公钥 pk。

```
攻击者有 pk  →  想加密什么，自己算就行
            →  等于免费送了他一台加密机
            →  窃听安全 = CPA 安全（K&L Prop 11.3）
```

**对比私钥版：OTP 是窃听安全的，但不是 CPA 安全的（钥匙复用就破，Lec 4 讲过）。**

所以对公钥来说，确定性的方案连最基本的窃听安全都做不到（K&L Thm 11.4）。迷你 RSA 就是这种，真实的 RSA 加密要先加随机填充。

### 顺带一个结论：公钥加密不可能完美保密

算力无限的攻击者手里有 pk，可以把所有消息、所有随机数都试一遍加密，看哪个能得到截获的密文，就知道原文了。所以公钥加密只能是计算安全的，Lec 7 那套计算安全的框架是必需的。

### 老师板书

```
Nature of attacks:  Chosen-plaintext attack (CPA)
Supervised learning
```

右边那个 Supervised learning 是老师的 crypto × ML 线索（Lec 6）：CPA 就像攻击者能**自己挑输入、拿到带标签的样本**（明文 → 密文）去学习加密函数。


## 4. GCD 与欧几里得算法

**做法已经会了**：HW1 Problem 1(a) 求 3⁻¹ mod 17 时，第一步的「辗转相除」就是欧几里得算法：

```
17 = 5 × 3 + 2
 3 = 1 × 2 + 1
 2 = 2 × 1 + 0     →  gcd(17, 3) = 1
```

板书上 `GCD(6,15) = 3` 也是一样算：`15 = 2×6 + 3`，`6 = 2×3 + 0`，答案 3。

**这一步真正新的只有两点：为什么对、为什么快。**

### ① 为什么对：gcd(a, b) = gcd(b, a mod b)

写成 `a = q×b + r`（r 就是余数）。

```
d 能整除 a 和 b   →   d 也能整除 r = a − q×b
d 能整除 b 和 r   →   d 也能整除 a = q×b + r
```

所以 **(a, b) 的公因数，和 (b, r) 的公因数，是同一批数**，最大的那个自然也一样。

**大白话：把大数换成余数，问题变小了，答案不变。** 一直换到能整除为止，就找到了。

### ② 为什么快：多项式时间

关键事实： 当 a > b 时，余数 `a mod b < a/2`。分两种情况：

```
b ≤ a/2：   余数比 b 还小    →  余数 < b ≤ a/2
b > a/2：   a 只装得下一个 b  →  余数 = a − b < a/2
```

**所以每两步，数字至少缩小一半。b 有多少位，最多就走 2 倍那么多步：**

> [!note]
> 一定要区分好，数字大小和位数！b有多少位，最多就走2b这么多步。

```
b 有 1024 位   →   最多 2048 步
```

实测两个 1024 位的随机数，只用了 **634 步**。

**为什么这很重要：** RSA 要对 1024 位的数求 gcd、求逆元。如果笨办法把所有可能的因数试一遍，要试 2¹⁰²⁴ 个，宇宙毁灭也算不完；欧几里得只要几百步。

**一个细节：** 这里的"多项式时间"是按**位数**算的，不是按数值大小算的。1024 位的数，数值本身大到约 2¹⁰²⁴，按数值算的话"试所有因数"看起来只是线性，其实是指数级。这就是 Lec 7 里 `1ⁿ` 那个问题：**算法快不快，要看输入有多长（多少位）**。

### 老师板书

```
÷（圈起来了）           ← 带余除法就是这个算法的核心
if b|a ⟹ d = b
else return GCD(b, a mod b)
terminates in 2 × bits(b)

```


## ‼️5. 定理：GCD 是 $I_{ab}$ 里最小的正数 ⭐

### 定义和证明

首先 $I_{ab}$ 的意思是：用 a 和 b 能凑出来的所有数。a 拿 A 份、b 拿 B 份，可以加也可以减。

定理：gcd(a, b) 在 $I_{ab}$ 里，而且是 $I_{ab}$ 里最小的正数

**主要是如何证明：**

记 d = gcd(a, b)，d* = I_ab 里最小的正数。分两半证明 d* = d：

```
① d* ≥ d
   d 整除 a 和 b   ⟹  d 整除任何 A·a + B·b
                   ⟹  d 整除 d*   ⟹  d* ≥ d
```

这半部分很好理解。


```
② d* ≤ d（板书主要写的是这一半）
   任取 I_ab 里一个数 A·a + B·b，用 d* 去除（c 是商，r 是余数）：
       A·a + B·b = c·d* + r,          0 ≤ r < d*
   d* 也是凑出来的，记 d* = X·a + Y·b，代进去：
       r = (A − cX)·a + (B − cY)·b    ← r 也是凑出来的，也在 I_ab 里
   r < d*，而 d* 已经是最小的正数  ⟹  r 只能是 0
   ⟹  d* 整除 I_ab 里每个数，包括 a 和 b 本身
   ⟹  d* 是公因数  ⟹  d* ≤ d
```

这个其实详细看一下，也是很好理解的。


### 有什么用

这个定理顺带告诉我们：gcd 一定能写成 X·a + Y·b。

当 gcd(a, n) = 1 时，就有 X·a + Y·n = 1，这里的 X 就是 a 在 mod n 下的逆元。RSA 算私钥靠的就是这个（第 6 步）。X、Y 具体怎么算，是第 7 步的扩展欧几里得。

### "gcd(b, N) = 1" 等价于 "b 在 mod N 下有逆元" 等价于 "b,N 互素"

**b 在 mod N 下有逆元 ⟺ gcd(b, N) = 1（Proposition 8.7）。**

注意这里是 b 和模数 N 的 gcd：

mod 12：  gcd(5, 12) = 1   →  5 有逆元（5×5 = 25 = 2×12 + 1）
          gcd(4, 12) = 4   →  4 没有逆元
mod 17：  17 是素数，1~16 跟它的 gcd 都是 1   →  全都有逆元
两个方向为什么成立，就是上次那两行：gcd = 1 时能凑出 1，所以有逆元；gcd = d > 1 时凑出来的全是 d 的倍数，凑不出 1，所以没有逆元。

顺带一提：第 8 步的 Z*_n，就是 mod n 下所有有逆元的数放在一起：{ b | gcd(b, n) = 1 }。

## 7. 扩展欧几里得：从手算到递归算法

代码会就可以了。

### 代码

输出 $[d, X, Y]$，满足 $d = \gcd(a, b) = Xa + Yb$。和第 4 步的普通版比，只改了两个地方：

```
普通版（第 4 步）                      扩展版（第 7 步）
if b | a:  return b                   if b | a:  return [b, 0, 1]
else:      return GCD(b, a mod b)     else:      a = c·b + r
                                                 [d, A, B] = ExtGCD(b, r)
                                                 return [d, B, A − B·c]
```

### 为什么返回 $[d, B, A - Bc]$

不用死记，一行就能推出来（板书推的就是这个）：

```
d = A·b + B·r，把 r 换成 a − c·b   →   d = B·a + (A − B·c)·b
```

### 怎么用

求 $b^{-1} \bmod N$：跑 $\mathrm{ExtGCD}(N, b)$，得到 $[1, X, Y]$，则 $b^{-1} = Y$（$Y$ 是负数就加上 $N$）。算具体的数（比如 $3^{-1} \bmod 17$），手算就行，结果和跑代码一样。

## 8. $\mathbb{Z}_n$ 与 $\mathbb{Z}^*_n$（复习）

- $Z_n$: mod n 下所有可能的余数
- $Z_n^*$: Z_n 里和 n 互素的数，也就是有逆元的数

```
Z_n  = {0, 1, ..., n−1}
Z_12 = {0, 1, ..., 11}
```

```
Z*_n = { r ∈ Z_n | gcd(r, n) = 1 }

Z*_12 = {1, 5, 7, 11}         0、2、3、4、6、8、9、10 和 12 有公因数，挖掉
Z*_17 = {1, 2, ..., 16}       17 是素数，只挖掉 0
```

**$Z_n^*$ 里有几个数: φ(n)（欧拉函数）**

- n 是素数 p：              φ(p) = p − 1
- n = p·q（两个不同素数）：  φ(n) = (p − 1)(q − 1)

很重要的结论。后面也会经常用到。
